## 3. Decisions made this session (for a fresh session to know without re-deriving)

- **Purchases is a placeholder, not a built module.** `apps/web/src/app/(protected)/purchases/page.tsx` is a bare "Coming soon" page. The Founder explicitly chose this over the alternatives (drop the third button, or build the real feature now) via `AskUserQuestion`. Manager's entry-point row does **not** yet have a Purchases button — only Staff's does; adding it to Manager was out of this session's scope.
- **"My submitted shift preferences" / "My work reports this week" / "Submit a correction request" sections are gone from `/staff`, on purpose**, per the Founder's own framing ("остальное... будет реализовано в таблице" — the rest will be implemented in "the table," i.e. some future redesign of the schedule table itself). Their component files (`shift-preference-form.tsx`, `work-report-form.tsx`, `correction-request-form.tsx`) were **not deleted** — they're orphaned-but-intact, likely to be reused/reintegrated when that table work happens. Do not delete them without checking with the Founder first, and do not assume this correction-request/work-report flow is gone forever — it's deferred, not cancelled.
- **The monthly shift-preference modal has no "unavailable" state**, by explicit Founder simplification (2026-08-24): a blank/untapped day already means "not working that day." The backend (`submitShiftPreference`/`submitMonthlyShiftPreferences`) still technically supports `isUnavailable: true` (a pre-existing single-day form used it, now retired from the UI), and old data with that flag set is displayed identically to a blank day rather than with a distinct visual state.
- **`RecipesPopup` now lives in `_ui/`, not `manager/`.** Any future reference to `manager/recipes-popup.tsx` is stale — the file moved, content unchanged, only its import path changed (`manager-dashboard-client.tsx` updated; `staff-dashboard-client.tsx` is a new importer).
- **Two real, independent bugs found and fixed via Founder QA, worth knowing about generally (not just for Staff)**:
  1. `submitWorkReport` (`attendance-actions.ts`) used to pass `null` (not `undefined`) for an omitted `transportationCost`/`dailyMessage`/clock field, which `buildAttendancePayload` (`attendance.ts`) then wrote as an explicit clear — any partial-field submission of this form silently erased whichever fields it didn't include. Fixed by checking `formData.has(...)` rather than the parsed value's nullness. This same fix pattern was already correctly applied on the preview-only surface (`previewSubmitWorkReport`) before this session; the production path had the bug.
  2. A `height` CSS property without `box-sizing: border-box` only sizes the content box, not the true rendered box — `padding`/`border` still add on top. This app has no global border-box reset, so any future fixed-height override on a padded/bordered element needs to set `boxSizing: 'border-box'` explicitly, or it silently does much less than intended (as happened with the entry-point buttons in #421→#422).
- **No DB migrations this session.** Every backend change (the monthly-preference batch action, the `details` jsonb note field, the `transportationCost`/`dailyMessage` independence fix) reused existing schema/RLS/columns.

## 5. Process notes reinforced this session

- Dev-merge via `bash scripts/ai-dev-merge.sh <PR#>` continues to work as the standing rule.
- **After a squash-merge, branch the next PR fresh off `origin/dev`.** Continuing to commit on the just-merged PR's own local branch and opening a second PR from it produces a false `CONFLICTING` state (the local branch's un-squashed history no longer matches `dev`'s new squashed commit for the same content) even when there is no real content conflict. This cost one throwaway PR (#420) this session before the pattern was corrected.
- The Founder's standing instruction this session: **always merge into `dev` immediately** (not wait for a separate "please merge" round) so Preview reflects the change for their own live QA — this is how the review loop (screenshot → fix → merge → re-screenshot) actually worked across all eight PRs.
