# QA4 — сценарий месяца (Cafe v2.2 Final Operational Simulation), 2026-10-18

Этап 3 roadmap (`docs/strategy/oruwa-roadmap-v2-2-close-to-production-2026-10-08.md`).
Цель: показать, что кафе может прожить **месяц** на ORUWA — все блоки,
кроме LINE, на правдоподобных данных — и закрыть Cafe v2.2.

Каждый пункт: **что сделать → что должно получиться**. Сначала прогон
делает Lead (результаты — в артефакте QA4), затем Founder проходит
раздел «Founder — финальный просмотр».

## 0. Как «месяц» получается честно

Приложение ставит время прихода/ухода, выполнения задач и пересчёта
по реальным часам сервера, поэтому прошлые дни нельзя «прокликать».
Поэтому три слоя:

| Слой | Что | Как |
|---|---|---|
| A. Прошлый месяц | 4 недели **2026-09-21 … 2026-10-17** | seed `packages/db/scripts/qa4-seed-past-month.sql` (Cloud DEV, тестовый арендатор `oruwa-cafe`) |
| B. Прошлые дни через продукт | исправление прошлой смены менеджером, запрос исправления от сотрудника | живые действия в разделе 7 |
| C. Живые дни | 3–5 рабочих дней QA4 (с 2026-10-19) | реальные приход/уход, HACCP, склад, закупки, почта, проблемы |

**Что создаёт seed (слой A)** — проверено локально (`qa4-seed-verify.sql`, 14/14 ok):

- опубликованные смены по нормативу дня (月1 火2 水2 木2 金3 土2 日1), не больше 5 дней / 40 ч в неделю, без двух смен в день, без дублей с уже существующими сменами;
- посещаемость по каждой смене: в основном вовремя, несколько опозданий, **одно отсутствие**, **одна смена без отметки ухода** (последняя смена одного сотрудника с аккаунтом — материал для раздела 7);
- HACCP: выполненный чек-лист с ответами за каждый день по каждому активному расписанию, кроме нескольких **намеренно пропущенных**; **два выхода температуры холодильника за 0–5 °C** (один решён менеджером с комментарием, один открыт);
- старый бэклог «пропущенных» проверок до 21.09 закрыт с пометкой `QA4 baseline … (DEBT-002)`; открытые «пропущенные» в окне, которые seed выполнил, удалены;
- 申し送り・問題報告: 10 записей (7 решено, 1 принято, 2 открыто), от сотрудников и менеджера;
- склад: пересчёт по пн/чт, заказ → приёмка через 2 дня, «куплено» для молока;
- メール: 7 сообщений сотрудник ↔ менеджер (прочитаны).

Не трогает: имена и PII (остаются зашифрованными), пожелания на ноябрь,
ноябрьский график, позиции с «QA» в названии. Каждая строка seed имеет id
`0a4a5eed-…`; очистка — `qa4-seed-cleanup.sql`, **только до живых действий
QA4** на seed-данных (закупка по seed-пересчёту, запрос исправления по
seed-посещаемости): после них очистка откажет и ничего не удалит.

## 2. Прошлый месяц глазами менеджера (слой A)
- [ ] 週間スケジュール → «前週» 1–4 раза → в каждой неделе 21.09–17.10 смены у всех пяти, нехватка только там, где норматив не закрыт.
- [ ] 概算人件費 за прошлые недели — сумма есть; «時給が未設定…» перечисляет тех, у кого нет ставки.
- [ ] スタッフ管理 → месячный отчёт (2026年9月 / 10月) → часы по сотрудникам ≈ сумма смен; отсутствие не считается часами.
- [ ] 週次レビュー за прошлые недели → посещаемость, опоздания, HACCP (выполнено / пропущено / вне диапазона), проблемы — числа совпадают с тем, что видно в блоках.
- [ ] 要確認 — больше нет сотен старых «пропущенных»; видны только пропуски в окне, открытый выход температуры и открытые проблемы.

## 3. Пожелания → автосоздание → публикация (ноябрь)
- [ ] Staff (田中, 鈴木) отправляют пожелания на ноябрь, включая «не могу».
- [ ] Manager: シフト希望 → видит, отмечает 承認.
- [ ] 自動でシフトを作成 → черновики уважают «не могу», 40 ч / 5 дней.
- [ ] Публикация → Staff видит смены сразу (без перезагрузки — раздел 12).

## 4. Неделя QA4: изменения смен
- [ ] Обмен сменой 田中 ↔ 鈴木 (запрос → ответ коллеги → решение менеджера).
- [ ] Отмена смены сотрудником → менеджер одобряет → ячейка пустеет у обоих.
- [ ] Менеджер меняет время чужой смены → сотрудник видит новое время.

## 5. Живые дни: приход/уход, транспорт, деньги
- [ ] Staff: 出勤 → 退勤 с перерывом → 交通費 → 日報.
- [ ] Manager видит приход в реальном времени; месячные часы и 推定 растут.
- [ ] Опоздание в живой день → статус «遅刻» в отчёте.
- [ ] Лимит месячных часов: при превышении автосоздание не ставит лишние смены.

## 6. Операции (HACCP)
- [ ] Staff выполняет 4 чек-листа дня; температура холодильника 7 °C → исключение «対応が必要».
- [ ] Морозильник −12 °C у `oruwa-cafe` → исключения **нет** (диапазон у этого кафе пустой — так задумано; стандартные диапазоны получат новые кафе, DEBT-100). Затем Manager ставит максимум −15 °C в шаблоне → следующий ответ −12 °C даёт исключение.
- [ ] Manager решает исключение с комментарием → оно уходит из 要確認, в истории видно кто и что.
- [ ] Пропущенная проверка дня → после окна появляется «未実施» в 要確認.

## 7. Исправления посещаемости (раздел 7 QA3, перенесён сюда)
- [ ] Staff **佐藤 陽介** (Staff B): смена 2026-10-16 10:00–14:00 без ухода (из seed) → «修正を依頼» → время ухода + сообщение.
- [ ] Manager: 要確認 → запрос → 承認 → в отчёте часы пересчитаны.
- [ ] Второй запрос → 却下 → сотрудник видит решение.
- [ ] Manager сам исправляет прошлую смену (過去のスケジュールを修正) → часы меняются.

## 8. Склад и закупки
- [ ] Пересчёт по всем единицам (kg, g, L, mL, pcs) → «不足» появляется при ≤ точки заказа.
- [ ] 仕入れ: заказ → приёмка (частичная тоже) → «購入済み»; повторное/невозможное действие (приёмка без заказа, двойная) даёт понятную ошибку.
- [ ] История закупок показывает месяц из seed + живые действия.

## 9. Рецепты
- [ ] Цена рецепта: все цены есть / одной нет / несовместимая единица → понятные состояния.
- [ ] Аллергены: блок 「アレルゲン情報」 + оговорка; JA/EN переключение.
- [ ] Расход склада по рецепту **не** списывается автоматически (так задумано).

## 10. Проблемы и передача смены
- [ ] Staff сообщает о проблеме → у менеджера «報告者: 名前» (новое, #595).
- [ ] Manager принимает → решает с комментарием → у Staff исчезает из 未解決.
- [ ] История показывает месяц из seed.

## 11. Почта
- [ ] 田中 → Manager, Manager → 田中, затем 鈴木 ↔ Manager: треды раздельны, счётчики непрочитанных верны.

## 12. Телефон и живые обновления (Realtime)
- [ ] Телефон, Staff: открыть /staff, заблокировать экран на 5+ минут, разблокировать → менеджер публикует смену / пишет сообщение → появляется **без ручной перезагрузки** в течение нескольких секунд.
- [ ] Переключение Wi-Fi ↔ мобильная сеть → обновления продолжают приходить.
- [ ] Ширина 375 px: все попапы читаемы, нет горизонтальной прокрутки.

## 13. Lead — технические проверки
- [ ] После seed: `qa4-seed-verify.sql` на Cloud DEV — все строки ok.
- [ ] Realtime: на телефоне (или эмуляции) кадры WebSocket после сна — переподключение, повторная подписка на `oruwa:<tenant>:staff|emp:<id>` (обёртка `window.WebSocket` через `initScript`).
- [ ] Стоимость: за день QA4 — вызовы функций Vercel по маршрутам, Realtime сообщения/подключения (Supabase Usage); записать в отчёт (вход для DEBT-097).
- [ ] Регрессия: CI, pgTAP (только DEBT-037), независимые ревью (general, DB/security, UX).

## Founder — финальный просмотр (≈30–40 минут)
1. Менеджер: 要確認 → понятно ли, что делать сегодня.
2. 週次レビュー за неделю из seed и за живую неделю.
3. Месячный отчёт по сотрудникам за октябрь.
4. Телефон Staff: приход → уход → сообщение менеджеру.
5. Решение: **Founder Acceptance PASS → Cafe v2.2 CLOSED** или список находок.

## Входы от Founder (одним списком)
- Алиасы почты для 1–2 новых сотрудников (`+staffd`, `+staffe`) — чтобы QA4 проверил приглашение нового человека и 4–6 активных Staff. Без них QA4 идёт с тремя Staff-аккаунтами.
- Отдельный QA-ящик (для писем-напоминаний/приглашений), если хотите, чтобы их проверял Lead, а не вы.

## Известные ограничения (не находки)
- Seed пишет напрямую в таблицы (как другие фикстуры) — для seed-строк нет записей аудита.
- «QAフィクスチャー…» позиции и старые QA-сообщения остаются до чистого демо-арендатора (этап 4D).
- Пороги HACCP у `oruwa-cafe` — свои (холодильник 0–5 °C на двух пунктах); стандартные диапазоны получат только новые кафе (DEBT-100).
